## SCOPE
NEW_FILE: scripts/veridian-task-watchdog.py
INPUT: none (scans /opt/veridian/ai-os/tasks/*/task.yaml, systemctl --user list-units veridian-worker@*)
OUTPUT: per run, JSON to ai-os/logs/watchdog.jsonl: {ts, task_id, status, stalled: bool, loop_detected: bool, action_taken: str}
LOGIC (exact):
  STALL = active_units>0 AND no new checkpoint entry appended in last 20 minutes (compare task.yaml checkpoints[-1].at to now)
  LOOP = last 3 checkpoints[].note are identical strings
  ON STALL_OR_LOOP:
    step_1: query ai-os/logs/ATTENTION.md + task_audits table for a prior entry whose note contains the same error-signature substring (first 60 chars of the stalled note)
    step_2: IF found AND that prior entry has a recorded fix action: apply the SAME fix action (documented per-signature in a new table `known_fixes`, columns: signature TEXT PRIMARY KEY, fix_action TEXT, last_applied TEXT, success_count INTEGER), log to known_fixes.last_applied, re-check status once after 60s
    step_3: IF step_2 not applicable or re-check still stalled/looping: escalate -- call `python3 scripts/veridian-task.py create --title "rca-<original-task-id>" --repo claude-control --prompt "<closed-ended RCA spec: read <original-task-id>'s task.yaml/worker.log/systemd.log, state root cause, apply a real fix, register the fix in the known_fixes table via a new superboss-register.py subcommand log-fix --signature --fix-action, so step_2 auto-resolves this signature next time>"`, then start that task's systemd unit

NEW_DB_TABLE: known_fixes in superboss-register.sqlite (see step_2 schema above), created via ALTER-safe CREATE TABLE IF NOT EXISTS in scripts/superboss-register.py's init_db(), plus a new subcommand `log-fix --signature --fix-action` (INSERT OR REPLACE, increment success_count on repeat)

SYSTEMD_TIMER: veridian-task-watchdog.timer, OnUnitActiveSec=60, calling veridian-task-watchdog.service (Type=oneshot, ExecStart=/usr/bin/python3 /opt/veridian/scripts/veridian-task-watchdog.py)
