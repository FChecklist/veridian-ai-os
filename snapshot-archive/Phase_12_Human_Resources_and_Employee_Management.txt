4. BUSINESS RULES
---

  4.1 Effective Dating (all modules)
    Every record has from_date/to_date. Records are valid
    only within this range. from_date is mandatory.

  4.2 Soft Delete / Status (all modules)
    status=0 Active, status=1 Inactive, status=2 Draft
    Records are never physically deleted. Status changes go
    through the workflow API (submitstatusdynamicworkflow).

6. CODE-LEVEL PATTERNS
---

  6.1 Generic Form Pattern
    All modules use views/new_from.php as the form renderer.
    The form HTML includes:
    - validateForm() JS function driven by mandatory_str
    - select2 dropdowns for FK fields
    - datepicker for date fields (jQuery UI)
    - Bootstrap 4 form layout (card > card-body > form-group)

  6.2 Hidden Metadata Pattern (every form)
    - option: The COM_ route constant
    - table_name: Physical DB table name
    - duplicate_table_name: For duplicate checking
    - in_date_pic: Array of date fields for datepicker init
    - in_currency_fileds: Currency fields for formatting
    - in_phone_fileds: Phone fields for validation
    - mandatory_str: Comma-separated required fields
    - notification_users: User IDs to notify on create
    - notification_message: Notification template

  6.3 DataTables Pattern (all list pages)
    - Uses custom AJAX, not built-in server-side mode
    - Supports CSV, Excel, PDF, Print export
    - Column visibility toggle
    - Status-based filtering
    - Text search via filter_text parameter
