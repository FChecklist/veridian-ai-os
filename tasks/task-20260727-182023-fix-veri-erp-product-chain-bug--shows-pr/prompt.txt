## KNOWN_CONTEXT
Live-reproduced on the current production deployment (veridian-aios.com, org `demo_org`, logged in as the demo CEO persona) on 2026-07-27, not a self-report — exact repro steps:
1. Go to `/chat`, click "VERI ERP" then "Product" in the chain-selector.
2. Only one option appears: "Demo Company Platform" (internal id, per the chain breadcrumb: `demo_product`).
3. Selecting "Demo Company Platform" shows TWO sub-options: "Website Revamp" and "ERP Rollout - Phase 2" (internal id, confirmed via the chain breadcrumb: `demo_project_website` for the first one) -- these are real Project entity names/ids, not Product sub-items.
4. Selecting "Website Revamp" offers these actions: "Status update", "Log a task", "Flag a risk" -- these are project-management actions. A correctly-scoped Product entity should offer product-management actions instead (e.g. update price/stock, create a quotation referencing the product -- check this codebase's own existing patterns for what a Product action set should actually contain).
By contrast, the sibling entities in the exact same chain-selector are correctly scoped and must NOT be modified: selecting "Customer" -> a real customer (e.g. "Orion Retail Chain Pvt. Ltd.", id `demo_cust_orion`) -> correctly offers "Invoice preparation", "Send reminder", "GST filing". Selecting "Vendor" also lists correctly-scoped real vendor names. This proves the bug is isolated to the "Product" entity branch of the chain-selector's data-resolution logic, not a systemic chain-selector defect -- use the working Customer/Vendor code path as the reference for what correct looks like.
