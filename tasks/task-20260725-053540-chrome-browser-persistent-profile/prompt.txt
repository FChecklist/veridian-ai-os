Install Google Chrome on VERIDIAN-DEV with a dedicated persistent browser profile at /opt/veridian/browser/profile, so future Playwright/Puppeteer-driven automation can reuse a real logged-in session instead of re-authenticating each run, per the Owner's directive INS-20260725-054500 (real architecture: Owner -> SSH -> VERIDIAN SERVER -> Chrome with persistent profile -> Playwright/Puppeteer/Claude Code CLI).

## KNOWN_CONTEXT

Read that entrypoint and its Playwright setup before building anything new, so this task reuses the existing Playwright installation/config on this server rather than installing a second, separate one.
- This server's real installed stack today is git, gh, Docker+Compose, Node 24 LTS, pnpm, Python 3.12, uv, Claude Code CLI -- no browser and no GUI/X11/VNC server currently installed or running.
- A Google account login step genuinely requires a human to type credentials and complete 2FA -- this is a hard constraint on the AI conducting this task (and on Claude Code sessions generally): no automated process, worker, or AI session may ever type a real password or 2FA code into any login form on the Owner's behalf. Build 100% of the real infrastructure (Chrome install, profile directory, security hardening, Playwright wiring, directory layout, a documented one-time-login procedure) but the actual "open Chrome and sign into Google" step is Owner-only manual action performed via remote desktop/VNC/X11-forwarding -- your job is to make that one manual step as short and well-documented as possible, not to attempt it yourself.

You will need to set up one of those (VNC recommended: lightweight, works over SSH tunnel, no need to expose ports publicly) purely so the Owner can complete the one-time login -- security-harden it accordingly (bind to localhost only, tunnel over SSH, tear down or firewall it back off after the Owner's one-time login rather than leaving a GUI service listening indefinitely).
- Owner's own directive already lists the concrete install commands, directory layout (/opt/veridian/browser/{chrome,profile,downloads,uploads,cache,screenshots,recordings,temp}), and security recommendations (dedicated Google account if possible, key-only SSH already true, restrict profile directory permissions to the automation user only, encrypt/back up the profile, do not run the browser as root). Follow that layout and those recommendations as the real baseline; add anything the real security review below finds missing.

3.
