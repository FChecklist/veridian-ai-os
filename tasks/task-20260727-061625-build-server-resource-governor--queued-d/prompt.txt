## OBJECTIVE
Build the SERVER RESOURCE GOVERNOR (Owner directive, 2026-07-27): a centralized execution queue that every scheduled trigger (cron, systemd timer, systemd worker spawn) must pass through, with a real per-metric 99% hard cap (CPU, RAM, disk I/O, network -- independently, any one hitting 99% freezes the queue), priority-tiered dynamic realignment, and a stuck-task SIGTERM/SIGKILL protocol. This is a direct, evidenced response to a real incident found and fixed this same day: `veridian-task-watchdog.timer` had been running unstopped for 9h18m, firing every 60s with no "is a worker already active for this issue" check, spawning duplicate workers that drove load average to 32 on this 8-core box. That specific failure mode -- an independent trigger firing straight into a spawn call with no shared gate -- is exactly what this governor must make structurally impossible.

## KNOWN_CONTEXT
`scripts/dispatch_core.py` (PR #101, merged and live) already provides a real flock-based `acquire_dispatch_lock()` and `running_worker_count()`/`has_free_slot()` against a single `CONCURRENCY_CAP` (currently 5), shared by every consolidated tick script (`dispatch-tick.py`, `phase-continuation-tick.py`, `status-remediation-tick.py`). That mechanism is a real, working COUNT-based gate but has two real gaps this task must close: (1) it only counts total concurrent units, so a trigger that fires every 60s and completes in under 60s can spawn an unbounded number of SEQUENTIAL duplicates without ever exceeding the count cap -- there is no "is this exact issue already queued or running" check; (2) it has no visibility into RAM/disk-I/O/network, only an implicit CPU-adjacent proxy via unit count plus the separate systemd slice `CPUQuota`/`MemoryMax` caps set during the OOM incident earlier this session. Do not replace `dispatch_core.py` -- extend it; every existing caller of `acquire_dispatch_lock()`/`has_free_slot()`/`record_dispatch_event()` must keep working unmodified.
`superboss-register.py` owns the real SQLite database at `ai-os/memory/superboss-register.sqlite` (already has `wiring_registry`, `knowledge_engine` tables). The Owner's spec calls for all task I/O (inputs, outputs, logs) to be logged to a searchable "Universal Task Metadata" record -- no such table exists yet; add one via `superboss-register.py`'s own real migration path (the same idempotent-migration pattern PR #101 already had to fix once for a schema-mismatch bug -- do not repeat that mistake, test the migration against a fixture DB seeded with the REAL current pre-migration schema, not a fresh one).
`veridian-task-watchdog.timer`/`.service` is the real example of an out-of-band trigger this governor must absorb -- it is currently stopped and disabled (do not re-enable it as part of this task); design the wrapper so that when it (or any future timer) is re-enabled, its `ExecStart` calls into the governor's queue-submission entrypoint instead of spawning a worker directly.

## SCOPE
1. Design and document the real priority tiers (0-4 per the Owner's spec) and map every existing trigger source (the 3 consolidated tick scripts, `veridian-task-watchdog.service`, `supervisor-sweep.sh`'s discovery-triggered `veridian-supervisor@` starts) to a tier.
2. Build `scripts/resource_governor.py`: a real submission API (`submit(task_spec, tier)`) that writes to a persistent queue table (part of the new UMR schema) instead of calling `systemctl start` directly; a real dispatcher loop/entrypoint that pulls the highest-priority queued item, checks all 4 real metrics via `/proc/stat` (CPU), `/proc/meminfo` (RAM), `/proc/diskstats` (disk I/O, delta-based rate) and `/proc/net/dev` (network, delta-based rate) against a configurable 99% threshold per metric, and only then calls `dispatch_core.acquire_dispatch_lock()` + the real `systemctl --user start` for that task's unit.
3. Implement dynamic realignment (Section 5 of the Owner's spec) and the stuck-task protocol (timeout -> SIGTERM -> 60s -> SIGKILL, using each unit's real systemd `ActiveEnterTimestamp` to measure elapsed time) and the emergency fail-safe cascade (Section 7) -- all as real, testable functions, not pseudocode.
4. Add the "is this exact issue already queued or running" de-duplication check specifically -- before any submission is queued, check both the queue table and `dispatch_core.running_worker_count()`-equivalent for an existing entry with the same target task/issue identity; reject (log, do not silently drop) a duplicate submission rather than queuing it. This is the specific fix for the watchdog-timer incident.
5. Extend `superboss-register.py` with the new UMR table (inputs/outputs/logs/tier/metric-snapshot-at-dispatch-time per task) via a real idempotent migration; add a query CLI (`--query-umr`) for searching it.
6. Wire `veridian-task-watchdog.service`'s `ExecStart` (do not touch its `.timer` -- leave disabled) to call the new governor's submission API instead of spawning a worker directly, as the concrete proof this closes the real incident.
7. Real tests: the count-based-cap-insufficient scenario (rapid-fire duplicate submissions of the same issue within a short window must produce exactly one queued/running entry, not N), a real per-metric-99%-freezes-queue scenario (mock or fixture the /proc reads), the stuck-task SIGTERM/SIGKILL escalation timing, and the UMR migration test against a realistic pre-existing (not fresh) schema fixture.

## SUCCESS_CRITERIA
`python3 -m pytest tests/ -k resource_governor -v` exits 0, covering at minimum: duplicate-submission rejection, per-metric 99% freeze, stuck-task kill escalation, and the UMR migration-against-pre-existing-schema test. `python3 scripts/resource_governor.py --query-umr --limit 5` runs against the live database and returns real rows without error.

A real PR against claude-control containing `scripts/resource_governor.py`, the `superboss-register.py` UMR migration, the updated `veridian-task-watchdog.service` unit file, the new tests, and a short design doc (`ai-os/SERVER_RESOURCE_GOVERNOR_2026-07-27.md`) documenting the tier mapping and the real incident this closes.
