## OBJECTIVE
Round 2 fix for PR #110 (claude-control, branch worker/task-20260727-061625-build-server-resource-governor--queued-d), the SERVER RESOURCE GOVERNOR built in response to the real veridian-task-watchdog.timer duplicate-spawn incident. The real audit (review.json on that task) rejected the PR for a genuine, empirically-reproduced race condition: `dispatch_one()` in scripts/resource_governor.py selects the next queued row via `next_queued_task()` BEFORE acquiring `dispatch_core.acquire_dispatch_lock()`, and never re-verifies the row's status once inside that lock before calling `_perform_spawn(row)`. The auditor reproduced this live with a two-thread race against the test fixture: both concurrent `dispatch_one()` calls selected and dispatched the SAME queued row, firing the real spawn action twice for the same task -- the exact duplicate-dispatch failure this whole feature exists to prevent. Everything else in the PR (schema, metric sampling, stuck-task SIGTERM/SIGKILL, emergency cascade, the other 15 tests) passed real review and does not need to change.
