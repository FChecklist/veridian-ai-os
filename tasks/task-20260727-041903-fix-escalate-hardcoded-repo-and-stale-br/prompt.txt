## OBJECTIVE
Fix two confirmed real bugs in VERIDIAN-DEV's auto-remediation "rca-" task-dispatch pipeline: (1) scripts/veridian-task-watchdog.py's escalate() function hardcodes --repo claude-control for every auto-escalated rca- task it creates, regardless of the stalled task's real repo (confirmed live in the currently deployed /opt/veridian/scripts/veridian-task-watchdog.py, ~line 287: `cmd = ["python3", VERIDIAN_TASK, "create", "--title", title, "--repo", "claude-control", "--prompt", prompt]`); (2) rca- retry task.yaml files have been observed starting with a stale/wrong branch field (literal "master" in real historical instances), which caused scripts/supervisor-entrypoint.sh to fail with "supervisor could not resolve a real PR for branch 'master'" when routing these tasks through a real audit.

## SCOPE
INPUT: scripts/veridian-task-watchdog.py (escalate(), load_task_yaml(), run loop ~line 244-376), scripts/veridian-task.py (cmd_create, cmd_checkpoint, cmd_adopt), scripts/task-gateway.py, scripts/prompt_gateway/*.py. Trace every real code path capable of creating an "rca-*" task.yaml and writing its initial repo/branch fields -- do not assume cmd_create is the only path without checking.
OUTPUT: escalate() must read the ORIGINAL stalled task's own task.yaml `repo:` field (already loaded via load_task_yaml() in the same function) and pass that real value as --repo to veridian-task.py create, instead of the hardcoded "claude-control" literal. Whatever code path is actually responsible for a new rca- task.yaml's branch field starting wrong/stale must be fixed so it either (a) carries forward a real, meaningful branch value it genuinely knows at creation time, or (b) leaves `branch` unset/null in task.yaml until a real git branch is known (e.g. at first real checkpoint), rather than silently writing a placeholder like "master" that supervisor-entrypoint.sh then tries to resolve a PR against and fails. If (b), also update supervisor-entrypoint.sh's read of task.yaml's branch field to treat unset/null as "not yet resolvable, re-check later" rather than a hard failure.
